# 豆包工作室 2.3.4 使用与 Agent 控制告知

- 生效版本：`2.3.4`
- Git 基线：`main@249f478`
- 发布状态：已实现、CI 通过、已合并、已安装验收、已发布
- 适用对象：人工使用者、自动化 Agent、维护者

## 当前权威行为

1. 每个账号使用唯一持久 Electron partition；启动时全部账号按单通道顺序预热并常驻。
2. 当前账号原位交互，后台账号移到屏外保活；不得通过复用 Webview 或 partition 加速切换。
3. 列表按“本次确认可用 → 已检测需处理 → 未确认/预热中”分组，同级保留置顶、额度、忙碌和用户原顺序。
4. Windows loopback 代理会进入 Electron NetworkService。2.3.4 首次启动只重建可再生缓存，不清 Cookie、Local Storage、IndexedDB 或登录 Session。
5. 平台状态不确定、登录/人机验证/额度/会员/未知弹窗存在时 fail-closed，不自动重复提交。

## 正式控制与诊断入口

- 正式 Agent 控制：以 `豆包工作室.exe --local-control` 启动，读取本机发现文件，使用短期 Bearer 令牌；先确认健康端点 `ready=true`，再用项目 ID、批次 ID 和任务 ID 调用 `start/pause/cancel/retry`。
- 开发者诊断：`--local-cdp` 默认关闭，只允许有人值守的短时诊断或隔离验收。用后退出应用并确认端口关闭。
- 禁止把长期 Computer Use、截图坐标、DOM 序号、跨会话元素编号或 CDP 脚本作为正式任务接口或完成证据。
- 两种入口都不得暴露到局域网或公网，不得输出 Cookie、Token、完整账号 Session、完整提示词、素材绝对路径或内部页面 URL。

协议、端点和错误码以 [`LOCAL_CONTROL.md`](LOCAL_CONTROL.md) 为准。

## CSV 与任务纪律

- 桌面按钮和拖放导入可在应用内使用。
- `import-csv` 是显式写入型 CLI，只能在豆包工作室完全退出后运行，并显式指定真实 `tasks.json` 与 `projects.json`。
- 项目必须使用真实 UUID；未知 `--project-id` 必须 fail-closed。创建项目使用 `--project-name`，同名不自动合并。
- 导入后先核对项目、批次、任务数、依赖、账号、模型、比例、时长和素材，再启动。
- “已导入、已排队、已提交、平台受理、已生成、已绑定、已下载、内容验收、可发布”是不同状态。

## 已知边界

- Dola 仅完成平台字段、Session/URL 边界和 CSV 账号消歧，尚未完成登录、提交、生成、产物和下载的真实端到端验收，当前不得声明可用。
- 完整 Capability API 的任务创建、资产上传、事件订阅、Webhook 与写入型 MCP 尚未开放。
- 豆包页面会变化；页面能力无法回读时应停止并更新适配器，不得降低安全门禁。

## 运维建议

- 始终只运行一个豆包工作室实例。
- 让启动预热自然完成；可用账号会自动前置，无需快速连点所有账号。
- 长时间自动化使用正式本机控制面，不让 Computer Use 或 CDP 宿主常驻。
- 发生黑屏、串层或账号身份错位时立即暂停该账号任务，记录账号 ID 与阶段，禁止通过复制其他账号 Session 修复。
